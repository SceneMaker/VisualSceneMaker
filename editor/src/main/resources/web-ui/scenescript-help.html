How to write and edit dialogue scripts in Visual SceneMaker

Overview

A SceneScript is the text file behind every scene in a project — the dialogue itself, grouped into scenes and turns, plus optional sections and notes for structuring the document, and inline commands for triggering character behavior (backgrounds, emotions, pauses, and more) at a precise point in the dialogue.

Scenes & turns

A scene starts with the scene keyword, a two-letter language code, and a name:

scene en warmup
Bob: Hello there, how are you doing today?
Alice: I'm doing well, thanks for asking!

Each turn is one line starting with Speaker: followed by one or more sentences. A new scene always starts with the scene keyword again.

Inline commands

Commands are written in square brackets inside a turn's dialogue text, and trigger an action at exactly that point in the utterance. In the editor's compact view they render as chips like these:

Bob: Let's begin. [background] Look around you. Bob: I'm so happy right now! [emotion joy]

The raw text behind those two chips looks like this:

Bob: Let's begin. [background image='park.jpg'] Look around you.
Bob: I'm so happy right now! [emotion type='joy' intensity='0.8']

A command's own actor defaults to the turn's speaker. To target a different character than the one speaking, prefix the command with that character's name: 

Bob: Watch this. [Alice: emotion type='surprise']

Common commands include:

CommandPurpose
backgroundChange the scene's background image or color
emotionPlay an emotional expression on a character
pauseHold the turn for a moment before continuing

Every agent configured in the project can declare its own commands — the insert dialog lists whichever commands are actually available, not just these three.

Blocking vs. fire-and-forget

In compact view, every command chip shows a small icon indicating whether it blocks the turn until it finishes, or fires without waiting:

IconMeaning
[pause 500] Blocking — always the case for pause, and for any command with the feature blocking='true'.
[emotion happy] Fire-and-forget — the default for everything else.

Sections

Sections are markdown-style headings used to structure a long script into readable parts — they are not dialogue and are never spoken. Use one, two, or three # characters for heading level: 

# Introduction

## Warm-up

### Task 1

Sections (and notes, below) only work between scenes — as their own line, separated from surrounding scene content by a blank line. There is no inline version.

Notes

Notes are short explanatory remarks for whoever is authoring or reviewing the script — reminders, instructions, or context — written in plain English, not code-style comments: 

Note: remember to smile before this line

scene en task
Bob: Let's begin.

Both sections and notes support **bold** and *italic* / _italic_ text.

Three views of a script

The toolbar button next to the script editor cycles through three ways of displaying the same script — each click moves to the next one, and the third click returns to the first. Your choice is remembered per project.

  • Code view — the raw text exactly as typed, including [...] brackets, # headings and Note: prefixes. This is also the only mode you can type directly into a heading or note.
  • Annotated text — a rendered, easier-to-read view: inline commands become labelled chips like [emotion happy], and headings/notes are styled. This is the default.
  • Text — for writing and reading the spoken words themselves. Commands fold away to narrow grey bars (), so a turn reads as continuous prose: Xenia:  Hallo  ich bin Xenia. Nothing is lost — hover a bar to read the command it stands for, and double-click it to edit it, exactly as in annotated text.

Editing inline commands

In annotated text and text view, an inline command is a chip (or folded bar) you can work with directly:

  • Ctrl+I (Cmd+I on Mac) with the cursor inside a turn opens the insert dialog — it lists the turn's own speaking agent's commands first, then every other configured agent in the project.
  • Double-click an existing chip to open the same dialog pre-filled, for editing its parameters or target agent.
  • Click a chip to select it, then press Backspace/Delete to remove it.
  • Drag a selected chip to move it elsewhere within the same turn.
  • Ctrl/Cmd+C copies the selected chip's exact command text; Ctrl/Cmd+V pastes it back in at the cursor.
  • Ctrl+Shift+I asks where a behavior belongs in the turn under the cursor, and opens the insert dialog at that position — see Suggested positions.

Suggested positions

Once you run the semantic analysis, the editor can suggest where in an utterance a behavior command belongs, based on where you have put comparable commands in this project before. Suggestions appear as faint dashed amber markers in the script and as rows under Suggested positions in the Semantic Analysis panel, grouped by turn.

Three things are worth knowing about what these are and are not:

  • They suggest a position, never a command. Accepting one opens the ordinary insert dialog at that position, so which behavior you use and how you configure it stays your decision. The suggestion has no opinion about that.
  • They only appear where the project has taught the model something. A new project shows none, and that is correct rather than a failure — there is nothing to learn from yet. They accumulate as you author, per project, and each row shows the support behind it so you can weigh a suggestion backed by one placement differently from one backed by a dozen.
  • Accepting counts for less than writing. A position you accepted from a suggestion is recorded as weaker evidence than one you chose unprompted, so the model cannot talk itself into confidence by agreeing with its own past output. Dismiss removes a suggestion and is recorded too.

Suggestions are recomputed from the analysis, so re-running the analysis after an edit refreshes them. Behaviors that do not accompany speech — a backdrop change, for instance — never get a suggested position, because they have no relationship to a position in the utterance.

SIA preview panel

The Preview panel lets you load a character and test Background/Emotion commands live before writing them into the script — use each column's "Insert at cursor" action to drop the exact command text at your current position in the script editor.
