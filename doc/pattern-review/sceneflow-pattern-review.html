How clearly do these interaction patterns describe themselves?

We are building authoring support for Visual SceneMaker, the system used to describe how a Socially Interactive Agent (SIA, right side) behaves and how it interacts with a person. When you plan a session with such an agent, you decide two different things. The first is what the agent says and shows, for example the wording of a question or a picture on the screen. The second is how the session proceeds: what comes first, what follows, how long the agent waits, what it does while it waits, and how it responds when the person does something you did not plan for.

Visual SceneMaker keeps these two apart, and this review is about the second one. It comes close to a session plan, in the way an interview schedule fixes the order of questions and says which one to skip when. Two things make it more than a plan on paper. It runs by itself, so timing is part of it. And it can respond while the session is under way, for instance when the person starts speaking or turns away.

In Visual SceneMaker this is called the flow. Today every flow has to be built from scratch. Instead, authors should be able to start from ready-made interaction patterns, which are recurring shapes such as “ask and wait for an answer” or “remind while waiting”.

Below are 23 candidate patterns, grouped into three levels of complexity. Each one is described in a single sentence and illustrated with a concrete example. In each example an agent acts, or an agent and a person interact.

Please rate for each pattern how understandable the description is. We are not asking whether you find the pattern useful, or whether you would need it in your own work. We want to know where the wording, the naming, or the grouping fails to communicate. Comments are optional. They are especially valuable where you rate something low.
